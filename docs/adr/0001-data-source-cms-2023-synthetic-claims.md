# ADR 0001: Build on the CMS 2023 synthetic Medicare claims, not DE-SynPUF

**Status:** Accepted · **Date:** 2026-10-18

## Context

This project models member-level payer claims: eligibility member-months, inpatient utilization per
1,000, cost per member per month (PMPM), and 30-day readmissions. It needs public, freely redistributable
claims and enrollment data. Two CMS synthetic sources fit:

| | CMS 2008-2010 DE-SynPUF | CMS synthetic Medicare claims (2023 release) |
|---|---|---|
| Years | 2008-2010 | Claims 2015-03 through 2023-03; enrollment files 2015-2025 |
| Diagnosis / procedure codes | ICD-9-CM | ICD-10-CM, ICD-10-PCS fields, HCPCS, MS-DRG |
| Enrollment detail | Annual coverage-month counts only | Monthly entitlement, Part C, Part D, and dual flags |
| Layout | Simplified DE-SynPUF layout | CCW research identifiable file (RIF) layout |
| Population | About 2.3 million synthetic beneficiaries in 20 samples | 8,671 synthetic beneficiaries |
| How it was made | Perturbed from real 2008-2010 claims | Generated by Synthea (no real records used) |

Facts about the 2023 release come from the CMS user guide (May 2023) and from inspecting the published
files on 2026-10-18:

- Files are pipe-delimited text with a header row. Dates are `dd-Mon-yyyy` (`25-Mar-2015`). Empty fields
  are usually a single space, not an empty string.
- `inpatient.csv` has 197 columns and 58,066 claim-line rows covering 20,867 claims (the user guide's
  Table 3-1 says 58,030). Claim-level fields repeat on every line of a claim.
- `beneficiary_YYYY.csv` uses the CCW Master Beneficiary Summary File long names
  (`MDCR_ENTLMT_BUYIN_IND_01`..`_12`, `HMO_IND_01`..`_12`, `DUAL_STUS_CD_01`..`_12`, ...): one row per
  beneficiary per year, 185 columns. The collection now has 2015 through 2025; the 2025 file has 10,000
  beneficiaries with only January-March populated, while claims stop on 2023-03-02.

## Decision

Use the CMS 2023 synthetic Medicare claims. Milestone 1 loads the beneficiary files and `inpatient.csv`.

## Why

1. **Member-months can be exact.** PMPM and per-1,000 rates are only as good as their denominator.
   Monthly entitlement flags give exact member-months. DE-SynPUF's annual counts
   (`BENE_HI_CVRAGE_TOT_MONS` and similar) do not say *which* months were covered, so every member-month
   would rest on an assumption (for example, that coverage is contiguous and ends in December).
2. **Current code sets.** ICD-10-CM is what payers process today. DE-SynPUF would need an ICD-9 to
   ICD-10 General Equivalence Mappings crosswalk just to make the data look modern, and the GEMs are
   approximate, one-to-many mappings that would add their own error.
3. **Research-file layout.** Column names match the CCW codebooks, so the models read like the code a
   payer or health-services research team would write against real RIF extracts.
4. **Incremental arrivals.** Enrollment already arrives as one file per year. The single inpatient
   file can be replayed as yearly arrivals by CMS processing date (`NCH_WKLY_PROC_DT`), so a claim with a
   December service date that was processed in January arrives with the next year's batch, just like
   real claims run-out.
5. **Redistribution.** CMS states the files "can be released publicly without restrictions", so a small
   subset can be committed as a test fixture.

## Consequences and known limits

- **Very limited inferential value.** CMS warns that the files "should not be used to draw conclusions
  about Medicare beneficiaries". Everything built on them here is an engineering demonstration, not a
  finding. Payments, lengths of stay, and claim-line counts are known to differ from real data
  (user guide, section 4).
- **The source has real coding defects.** Many injury codes lack their required 7th character
  (`S134XX`, `T7432X`), and the procedure fields often hold ICD-10-CM diagnosis codes (`Z741`, `G4730`)
  or truncated codes (`GZ3`) instead of 7-character ICD-10-PCS codes. Because these defects are
  systemic, code-set conformance is measured and reported per code, not used to quarantine claims
  (see the code-validation notes in the README).
- **ICD-10 before it was effective.** ICD-10 took effect for discharges on or after 2015-10-01, but the
  generator writes ICD-10 codes on 2015 claims from March onward. Those claims are flagged.
- **Part C does not suppress fee-for-service claims.** Synthea simulates Medicare Advantage (Part C)
  enrollment but still exports fee-for-service claims for those members. A CCW-style FFS denominator
  that drops Part C months would therefore overstate PMPM. Member-months keep both flags and document
  the choice.
- **Small volume.** 8,671 members are too few to benchmark Spark. The Spark milestone will scale up the
  population with Synthea's open-source RIF exporter (or add DE-SynPUF as a second, high-volume source)
  rather than drawing conclusions from this file.
